# Mock Backend 关键接口改动说明

## 1. Redis 快速解析缓存

用途：保存会话级临时文档正文，供 `chat_on_docs` 拼接上下文。

Redis Key：

```text
quick_parse:{session_id}
```

TTL：

```text
7200 秒
```

配置参数：

```env
REDIS_URL=redis://mock_redis:6379/0
```

Docker 暴露端口：

```text
宿主机: 127.0.0.1:6380
容器内: mock_redis:6379
```

常用调试命令：

```bash
docker exec -it mock_backend_redis redis-cli
KEYS quick_parse:*
GET quick_parse:{session_id}
TTL quick_parse:{session_id}
```

## 2. quick_parse 接口

接口：

```http
POST /quick_parse?session_id={session_id}
Content-Type: multipart/form-data
```

参数：

| 参数 | 位置 | 说明 |
| --- | --- | --- |
| `session_id` | Query | 当前会话 ID |
| `file` | FormData | 上传文件 |

支持格式：

```text
pdf / docx / txt
```

限制：

```text
PDF <= 4 页
TXT / DOCX <= 4000 字符
Redis TTL = 2 小时
```

成功流程：

```text
校验 session 归属
读取并解析文件
写入 Redis: quick_parse:{session_id}
将旧 cached quick 记录更新为 expired
新增 document_uploads 记录:
  parse_type = quick
  status = cached
  content_length = 解析文本长度
  expires_at = 当前时间 + 7200 秒
```

失败流程：

```text
新增 document_uploads 记录:
  parse_type = quick
  status = failed
  error_message = 失败原因
  error_code = HTTP 状态码
```

## 3. chat_on_docs 状态流转

接口：

```http
POST /chat_on_docs?session_id={session_id}
Content-Type: application/json
```

请求体：

```json
{
  "message": "用户问题"
}
```

消息状态：

```text
pending -> retrieving -> generating -> completed
```

异常状态：

```text
任意阶段 -> failed
```

落库字段：

| 字段 | 说明 |
| --- | --- |
| `status` | 当前消息状态 |
| `documents` | 引用文档 JSON 字符串 |
| `recommended_questions` | 推荐问题 JSON 字符串 |
| `think` | mock 推理说明 |
| `retrieval_time_ms` | 检索耗时 |
| `generation_time_ms` | 生成耗时 |
| `started_at` | 开始时间 |
| `completed_at` | 完成或失败时间 |
| `error_message` | 失败原因 |

SSE 协议：

```text
event: message
data: {"documents": [...]}

event: message
data: {"content": "..."}

event: message
data: {"recommended_questions": [...]}

event: end
data: [DONE]
```

异常 SSE：

```text
event: error
data: {"error": "错误信息", "status": "failed"}

event: end
data: [DONE]
```

## 4. 引用文档字段

`chat_on_docs` 会从 Redis 读取快速解析内容，并组装为引用文档。

引用字段同时兼容 mock 后端和前端标准字段：

```json
{
  "id": "quick_parse:{session_id}",
  "document_id": "quick_parse:{session_id}",
  "document_name": "快速解析文档",
  "content_with_weight": "全量解析内容",
  "positions": [],
  "doc_id": "quick_parse:{session_id}",
  "doc_name": "快速解析文档",
  "content": "全量解析内容",
  "similarity": 1.0,
  "source": "quick_parse"
}
```

注意：

```text
documents.content 和 documents.content_with_weight 均返回全量内容。
```

## 5. get_messages 历史消息

接口：

```http
GET /get_messages?session_id={session_id}
```

行为：

```text
校验 session 归属
按 created_at 升序返回 messages
如果历史 documents 中 quick_parse 内容被截断，且 Redis 内容未过期，则返回时用 Redis 全量内容补齐
```

返回中的关键字段：

```text
documents
recommended_questions
think
status
retrieval_time_ms
generation_time_ms
started_at
completed_at
error_message
```

## 6. knowledgebases 文件管理接口

文件列表：

```http
GET /get_files
```

上传文件：

```http
POST /upload_files
Content-Type: multipart/form-data
```

参数：

| 参数 | 位置 | 说明 |
| --- | --- | --- |
| `files` | FormData | 多文件上传 |
| `session_id` | Query，可选 | 兼容真实接口，mock 中文件归属仍按 user_id |

删除文件：

```http
DELETE /delete_file/{file_name}
```

上传限制：

```text
支持 pdf / doc / docx / txt
同一用户下 file_name 不允许重复
文件保存路径: mock_backend/storage/file/{user_id}/{file_name}
```

数据库表：

```text
knowledgebases
```

核心字段：

```text
user_id
file_name
status
error_message
created_at
updated_at
```
